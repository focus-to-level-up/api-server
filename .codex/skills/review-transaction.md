# Skill: review-transaction

## 목적

데이터 정합성 위험이 있는 변경을 검토할 때 따르는 절차다.

## 사용 시점

- 집중 시간 저장 변경
- 보상 지급 변경
- 우편함 수령 변경
- 결제 webhook 변경
- 랭킹/주간 보상 정산 변경
- 관리자 수동 지급/수정 변경

## 절차

1. 변경되는 데이터와 테이블을 나열한다.
2. 같은 요청이 두 번 들어오는 경우를 확인한다.
3. 같은 사용자가 동시에 요청하는 경우를 확인한다.
4. DB 트랜잭션 경계를 확인한다.
5. Redis 락이 필요하면 락 키와 TTL을 정의한다.
6. 실패 후 재시도 시 결과가 안전한지 확인한다.
7. 필요한 방어선을 정한다.
8. 남은 리스크를 기록한다.

## 권장 방어선

- 멱등성 키
- DB unique constraint
- 상태 값 기반 전이 검증
- 지급/정산 이력
- Redis 분산락
- 재처리 가능한 Batch 상태
