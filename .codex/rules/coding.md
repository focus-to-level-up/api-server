# Coding Rules

## 목적

Spring Boot 서버 코드를 수정할 때 지켜야 하는 기본 코딩 규칙을 정의한다.

## 기본 원칙

- 기존 패키지 구조와 네이밍을 우선 따른다.
- 요청 범위를 벗어난 리팩터링을 하지 않는다.
- Controller는 얇게 유지하고, 핵심 흐름은 Service에 둔다.
- 도메인 규칙은 가능한 한 `levelup-domain`에 둔다.
- 기술 구현은 가능한 한 `levelup-infra`에 둔다.
- 범용 유틸리티만 `levelup-common`에 둔다.

## DTO와 응답

- API/Admin 전용 DTO를 공유 모듈에 두지 않는다.
- Request/Response DTO는 호출 주체가 이해하기 쉬운 이름을 사용한다.
- 기존 응답 형식과 에러 형식을 유지한다.
- 모바일 앱 호환성이 있는 응답은 임의로 필드명을 변경하지 않는다.

## 예외 처리

- 기존 예외 계층을 우선 따른다.
- 사용자에게 노출되는 메시지와 서버 로그용 메시지를 구분한다.
- 결제, 보상, 랭킹, 관리자 작업의 실패는 원인 추적이 가능해야 한다.

## 문서 갱신

- 의미 있는 기능 변경 후에는 `docs/harness/PROGRESS.md`를 갱신한다.
- 구조나 정책이 바뀌면 `ARCHITECTURE.md` 또는 `DECISIONS.md`를 갱신한다.
