# Integrity Rules

## 목적

집중 시간, 보상, 결제, 랭킹, 배치 정산처럼 데이터 정합성이 중요한 기능의 검토 기준을 정의한다.

## 고위험 영역

- 집중 시간 저장
- 경험치, 골드, 다이아 지급
- 우편함 수령
- 출석 체크
- 친구 초대 보상
- 주간 랭킹 정산
- 주간 보상
- RevenueCat webhook
- 관리자 수동 지급/수정

## 필수 검토

- 같은 요청이 반복되어도 결과가 한 번만 반영되는가?
- 동시에 여러 요청이 들어와도 중복 지급되지 않는가?
- DB 트랜잭션 경계가 명확한가?
- Redis 락을 쓴다면 락 키와 TTL이 명확한가?
- 실패 후 재시도해도 안전한가?
- Batch를 재실행해도 같은 보상이 두 번 지급되지 않는가?
- webhook이 중복 전달되어도 상태가 깨지지 않는가?

## 권장 방어선

- 멱등성 키
- DB unique constraint
- 상태 값 기반 전이 검증
- 지급/정산 이력 테이블
- Redis 분산락
- 재처리 가능한 Batch 상태 설계
