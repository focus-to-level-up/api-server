# Admin 리그·랭킹 관리 화면 설계

마지막 갱신: 2026-06-10

## 목적

기존 Admin 리그·랭킹 REST API를 Thymeleaf MVC 화면으로 전환한다.
운영자가 리그를 빠르게 전환하며 소속 회원과 인원 정합성을 확인할 수 있도록 한다.

## 화면 구조

### 마스터·디테일 동시 조회

- 왼쪽 영역에는 활성 리그 목록을 표시한다.
- 오른쪽 영역에는 선택한 리그 정보와 전체 랭킹 회원을 표시한다.
- 모바일 또는 좁은 화면에서는 리그 목록과 랭킹 상세를 세로로 배치한다.
- 선택한 리그, 검색 조건은 URL 쿼리 파라미터로 유지한다.

### 리그 목록

- 활성 리그를 기본 조회한다.
- 카테고리와 티어 필터를 제공한다.
- 현재 시즌 종료 시 기존 리그가 제거되므로 페이지네이션 없이 전체 표시한다.
- 비활성 리그가 존재하면 상태 필터를 통해 조회할 수 있도록 한다.

### 랭킹 회원 목록

- 리그당 예상 인원은 80~110명이므로 페이지네이션 없이 전체 표시한다.
- 목록 영역에 고정 높이와 세로 스크롤을 적용한다.
- 서버 렌더링 방식으로 회원 ID 또는 닉네임을 검색한다.
- 검색은 입력할 때마다 실행하지 않고 검색 버튼 또는 Enter 제출 시 실행한다.
- 순위, 회원 ID, 닉네임, 레벨, 상태를 표시한다.
- `socialId`는 노출하지 않는다.
- 회원 ID 또는 닉네임을 누르면 회원 관리 상세 화면으로 이동한다.

## 인원 정합성

- `Ranking` 행을 회원의 실제 리그 소속을 나타내는 원본 데이터로 본다.
- 실제 인원은 선택 리그의 Ranking 개수로 계산한다.
- `League.currentMembers`는 조회 최적화를 위한 파생 카운터로 본다.
- 두 값이 다르면 Admin 화면에 불일치 경고와 차이를 표시한다.
- Admin 화면에서는 인원수를 직접 수정하는 기능을 제공하지 않는다.
- 정합성 복구는 향후 Batch 점검·복구 작업으로 분리한다.
- 실제 Ranking 인원이 예상 범위인 80~110명을 벗어나면 운영 경고를 표시한다.

## 랭킹 정지·복구 정책

### 랭킹 정지

- `ACTIVE` 상태이며 Ranking이 존재하는 회원만 정지할 수 있다.
- 정지 시 회원 상태를 `RANKING_BANNED`로 변경한다.
- Ranking을 삭제하고 해당 리그의 `currentMembers`를 감소시킨다.
- 경고 우편에는 1주 동안 랭킹 참여가 정지된다고 안내한다.
- 화면에서 정지 전 확인 절차를 제공한다.

### 자동 복구

- 정지일로부터 1주 후 Batch가 자동 복구한다.
- 기존 티어와 관계없이 회원 카테고리의 가장 인원이 적은 브론즈 리그로 배치한다.
- Ranking 생성과 대상 리그의 `currentMembers` 증가는 같은 처리 흐름에서 수행한다.

### 관리자 수동 복구

- 관리자는 정지 기간이 지나지 않았어도 즉시 복구할 수 있다.
- 수동 복구도 기존 티어와 관계없이 브론즈 리그로 배치한다.
- 회원 관리 화면의 기존 복구 기능을 사용한다.
- 향후 감사 로그 도입 시 작업 관리자와 복구 사유를 기록한다.

## Spring Boot 구조

### Controller

- 기존 `AdminRankingController`를 `@Controller` 기반 MVC Controller로 전환한다.
- `GET /leagues`에서 리그 목록, 선택 리그, 랭킹 목록을 한 화면에 렌더링한다.
- 필터와 검색 조건은 쿼리 파라미터로 받는다.
- 랭킹 정지는 POST 요청과 CSRF 검증을 사용한다.
- 업무 예외는 기존 Admin flash 오류 처리 방식으로 선택 리그 화면에 표시한다.

### Service

- `AdminLeagueService`는 필터 조건에 맞는 리그 목록을 조회한다.
- `AdminRankingService`는 선택 리그의 정렬된 Ranking 전체를 조회한다.
- 화면 응답 DTO에서 실제 Ranking 인원, 저장된 인원, 차이, 경고 여부를 계산한다.
- 랭킹 정지 로직은 회원 관리 화면과 리그 화면이 동일한 서비스를 사용한다.
- `AdminMemberService.restoreMember`는 브론즈 리그 복구 정책으로 변경한다.

### Repository

- 리그 목록은 활성 상태, 카테고리, 티어 조건 조회를 지원한다.
- 랭킹 목록은 기존 레벨·경험치 내림차순 정렬을 유지한다.
- `Ranking.member_id`의 유일성 제약 여부를 후속 정합성 점검 항목으로 확인한다.

## 오류 처리

- 선택한 리그가 없으면 현재 필터에 포함된 첫 번째 활성 리그를 기본 선택한다.
- 조건에 맞는 리그가 없으면 빈 상태를 표시한다.
- 선택 리그가 존재하지 않으면 리그 목록으로 돌아가 오류 메시지를 표시한다.
- 허용되지 않은 랭킹 정지 요청은 선택 리그와 검색어를 유지하고 flash 오류를 표시한다.
- 예상하지 못한 오류는 Admin 공통 오류 화면에서 처리한다.

## 테스트 범위

- 리그 목록 필터와 기본 리그 선택
- 선택 리그의 랭킹 목록과 실제 인원 계산
- `currentMembers` 불일치 탐지
- 회원 ID·닉네임 서버 검색
- `socialId`가 응답 DTO와 화면에 노출되지 않는지 확인
- 랭킹 정지 후 선택 리그와 검색 조건 유지
- 1주 자동 복구 대상 조회
- 자동·수동 복구 시 브론즈 리그 배치와 `currentMembers` 증가
